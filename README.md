# 跨境企业撮合履约

支持跨境企业从会前配对、现场洽谈到会后合作落地。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括峰会秘书处、境内企业、东盟企业、专业服务机构。

资料所依据的领域事实如下：

- 会前通过系统预配对大量供需信息
- 现场设置多个行业对接会和一对一洽谈区
- 会后线索将沉淀并继续提供全年服务

## 平台模块

峰会闭幕后，秘书处对全部供需信息持续负责。平台按以下主线全年运营：

| 模块 | 职责 |
| --- | --- |
| `src/registry.js` | 主体治理：注册号/名称规范化识别重复主体，合并留痕；授权联系人按范围行事，支持临时更换与授权过期 |
| `src/records.js` | 供需记录：版本化管理，企业改需求即升版本 |
| `src/matching.js` | 可解释匹配：依据行业能力、需求条件、禁配关系、语言与可用时段给出候选，每条候选附理由，被排除组合也记录原因 |
| `src/scheduling.js` | 洽谈排程：双方确认才占用一对一席位；时段冲突、需求变更、代表更换时自动释放资源并通知相关方，空出席位自动补给等待会议 |
| `src/fulfillment.js` | 会后履约：保密纪要、意向金额、政策咨询、法律服务、投融资事项沿同一合作关系推进；保密条目未经双方同意不得扩散 |
| `src/platform.js` | 门面：把上述模块与通知中心串成一条主线 |

关键规则：

- 只有双方确认才占用一对一洽谈席位；单方确认只进入待确认状态。
- 代表临时更换、企业改需求、同一企业同时段被安排多场活动时，平台释放所占资源并通知双方联系人与秘书处。
- 主办方视图只看到签约、明确终止及其原因；企业视图看到下一行动与当前责任人；第三方只能看到经双方同意披露的条目。
- 仓库不保存账号、密钥、连接串或真实身份信息，测试与演示均使用示例数据。

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。运行项目自带测试即可检查这些基础资料能够稳定读取。

```bash
npm test        # 全部单元测试、端到端测试与 4700+ 规模测试
npm run demo    # 演示从闭幕后导入到签约的完整流程
```
