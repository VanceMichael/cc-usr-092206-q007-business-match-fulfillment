# 跨境企业撮合履约

支持跨境企业从会前配对、现场洽谈到会后合作落地的全年运营平台。峰会闭幕后，
四千七百多条供需信息不再停留在参会人员的名片夹里：谁和谁真正谈过、谁承诺
跟进、意向为什么没有继续，全部沉淀为系统中可追溯的数据。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json`
保存不含真实个人信息的示例。当前参与方包括峰会秘书处、境内企业、东盟企业、
专业服务机构。

资料所依据的领域事实如下：

- 会前通过系统预配对大量供需信息
- 现场设置多个行业对接会和一对一洽谈区
- 会后线索将沉淀并继续提供全年服务

## 平台如何回应这些要求

代码按四个领域模块组织，全部为零依赖的 Node ESM，入口在
`src/platform.js`（`MatchPlatform` 门面）：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 主体治理 | `src/identity.js` | 重复主体识别合并、授权联系人（范围/有效期/更换） |
| 可解释匹配 | `src/matching.js` | 硬门槛 + 评分，候选与拒绝都带中文理由 |
| 洽谈排程 | `src/scheduling.js` | 双方确认才占座、候补补位、变更即释放并通知 |
| 会后履约 | `src/fulfillment.js` | 同一合作关系推进事项、双方同意才扩散、双视图 |

辅助工具：`src/util-time.js`（周期时段交集、日期校验）。

### 1. 重复主体与授权联系人

- 统一社会信用代码一致 → 自动合并；规范化名称（去空白、全角半角、大小写、
  组织后缀差异）一致 → 自动合并；名称高相似且同注册地 → 挂起秘书处人工
  确认（`confirmMerge` / `rejectMerge`），不自动合并。
- 合并保留全部 `sourceRefs` 来源，能力/需求取并集。
- 联系人授权按范围划分：`match`（确认配对）、`meeting`（确认/改约席位）、
  `fulfillment`（推进会后事项与扩散同意）、`admin`（改资料与授权他人），
  并带 `validFrom` / `validUntil`。代表临时更换时旧代表失效、继任者继承
  未到期授权。

### 2. 带理由的候选

对「需求 × 候选」先过硬门槛，任一不过即进入拒绝清单并附原因：

- **禁配关系**：秘书处登记的禁配主体对/禁入区域、企业自报禁运区域
- **行业能力**：产品类目与行业是否对口
- **需求条件**：资质认证、目标服务区域、最小数量与年产能、价格上限
- **语言**：双方授权联系人（优先）或企业至少一种共同工作语言
- **可用时段**：周期性可用窗口存在交集

通过门槛的候选按行业、产能富余、区域覆盖、价格、语言、时段宽度、历史合作
打 0–100 分，逐因素输出理由（演示与 `recommend()` 返回值可见）。

### 3. 席位只有双方确认才占用

- 提议不占任何资源；一方确认仍不占；双方授权联系人都确认后才锁定席位。
- 席位已满自动进入候补队列，席位释放时按顺序补位并通知双方。
- 同一代表被排进时间重叠的两场活动时，第二次确认被阻止；秘书处也可用
  `resolveDoubleBookings` 主动清理。
- 代表更换 → 其确认全部作废、已占席位立即释放、双方收到通知，需新代表
  重新确认；企业改需求/撤需求 → 关联未举行会谈失效（`invalidated`）并
  释放资源；取消/谢绝/超时同样释放并触发候补补位。

### 4. 会后事项沿同一合作关系推进

- 会谈标记举行即建立（或复用）唯一合作关系；保密纪要、意向金额、政策
  咨询、法律服务、投融资都是挂在该关系上的「事项」，每个事项有下一行动、
  当前责任人与期限。
- 事项内容默认仅双方可见；向第三方（含主办方）扩散必须双方各持
  `fulfillment` 授权的联系人分别同意，且按事项粒度授权。
- **主办方视图**只呈现终态：已签约（合同编号）或已终止及原因，进行中
  关系不暴露金额与内容；**企业视图**呈现每个事项的下一行动与责任人。

## 本地校验与演示

```bash
npm test     # 31 个测试：主体治理、匹配、排程、履约与端到端（含 4700 条导入去重）
npm run demo # 走完一整年流程的中文端到端演示
```

仓库不保存账号、密钥、连接串或真实身份信息；演示与夹具中的企业、联系人均
为虚构示例。
